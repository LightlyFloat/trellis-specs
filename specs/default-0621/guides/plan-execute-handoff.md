# 规划与执行分离规范

> 适用范围：使用 Trellis 工作流的所有项目。
> 目的：把规划与执行拆到两个会话，使执行期不背负规划期上下文，
> 并使两个阶段可以分别选用不同能力档次的模型。

---

## 一、为什么要分离

规划与执行在同一会话内连续进行会带来两个后果。其一，规划期积累的全部上下文继续压在
执行期，而执行期真正需要的只是最终结论。其二，无法按阶段分配模型，规划需要能力较高
的模型，执行更适合速度快、性价比更好的模型，同一会话无法兼顾两者。

---

## 二、停止点

规划会话在 Phase 1.4 的 `task.py start` **执行成功之后**停止，不得继续进入 Phase 2.1。

停在 `start` 之后而非之前，理由是 `start` 本身就是既有评审门的完成标志，任务状态翻到
`in_progress` 正确表达了「规划已完成且已获批准」。若停在 `start` 之前，执行会话必须
重做评审门，用户需要批准两次。

判定信号：**同一会话内执行过 `task.py start`，则本会话即规划会话，不得继续进入 2.1。**
这是一个可靠的会话内信号，不依赖任何外部状态。

---

## 三、交接不能依赖指针自动解析

执行会话不能假定 active task 指针会自动指向正确的任务，理由有三条。

第一，active task 指针按会话存储。`active_task.py` 中的
`_resolve_single_session_fallback` 在 session 文件数为 0 或大于等于 2 时返回 `None`，
刻意拒绝跨窗口猜测，以此保住多会话隔离契约。只要环境中存在两个以上会话文件，
自动回退解析必然失败。

第二，指针写入本身可能降级。`task.py` 中降级模式的注释明确写着
「common on Windows + Claude Code」，说明在该环境下指针有可能根本写不进去。

第三，清空会话是否更换 session id 无法在会话内验证，因此不能作为前提依赖。

结论：**交接话术必须显式点名任务目录，并重跑 `task.py start` 重建指针。**

---

## 四、`task.py start` 可安全重跑

重跑 `start` 不会破坏任务状态。`task.py` 中的状态翻转只在当前状态为 `planning` 时执行，
已经处于 `in_progress` 的任务重跑不改变状态；同一路径上的 `set_active_task` 会重建
指针，这正是交接所需的效果。

已知副作用：每次 `start` 都会触发 `after_start` 钩子。默认配置中该钩子全部处于注释
状态，未定义任何动作，影响可忽略。若项目自行启用了 `after_start` 钩子，须先确认该钩子
可重复执行。

---

## 五、`implement.md` 必须可冷读

本规范不新增交接文档格式。交接载体沿用既有的 `implement.md`，接续入口沿用既有的
`/trellis:continue`。新增的是对 `implement.md` 的可冷读约束。

可冷读指执行会话在零先前上下文的条件下即可完整执行。五条要求如下：

- 每个步骤写明仓库相对路径，禁止使用「上面那个文件」「前述模块」之类的指代
- 每个步骤附带可直接粘贴运行的验证命令
- 关键决策的理由写在 `design.md`，`implement.md` 以小节号引用，执行会话无需重新推导
- 显式列出禁止改动的范围，防止执行会话擅自扩大范围
- 显式列出回滚点

---

## 六、规划会话的终止输出

规划会话停止前必须输出五项内容：

1. 产物清单及其路径
2. 待执行改动的一句话摘要
3. 执行会话的建议名称
4. 任务路径已填好的可粘贴接续话术
5. 建议的模型切换

---

## 七、会话命名约定

| 会话 | 名称格式 | 示例，任务目录为 `09-25-spec-workflow-split` |
|---|---|---|
| 规划会话 | `plan-<slug>` | `plan-spec-workflow-split` |
| 执行会话 | `exec-<slug>` | `exec-spec-workflow-split` |

`<slug>` 取任务目录名去掉日期前缀。该格式使会话名与任务目录可双向追溯，由任务名可推出
会话名，由会话名可定位任务目录。

名称由规划会话主动给出，由用户自行应用到会话标题。本约定不依赖任何平台提供的重命名
命令，因此跨平台可用。

---

## 八、用户动作序列

规划会话的终止输出中须按以下顺序给出四步，其中命名动作不可省略：

1. 切换模型，规划使用能力较高的模型，执行使用速度快且性价比更好的模型
2. 清空会话
3. 按第七节的约定命名新会话
4. 粘贴接续话术

接续话术模板，其中 `<TASK_DIR>` 由规划会话填入实际路径：

```text
接续任务 <TASK_DIR>。

先执行 python ./.trellis/scripts/task.py start <TASK_DIR>
重建 active task 指针（上一会话已 start 过，这里是 /clear 后重建，任务状态不会变）。

上一会话已完成全部规划，prd.md、design.md、implement.md 均已评审通过。
请读这三份产物，按 implement.md 的清单从 Phase 2.1 开始实施。
不要重新规划、不要修改规划产物、不要派发 trellis-implement 子代理。
```

末行的子代理约束依据 [子代理使用边界规范](./subagent-boundary.md)。

---

## 九、验证

- 规划完成后 AI 主动停止并给出终止输出的五项内容，不自行进入 2.1
- 执行会话按话术启动后，能在零先前上下文下定位到任务、读到 `implement.md`
  并从 2.1 开始，不重新规划
